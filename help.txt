	El frontend se sirve directamente por Nginx global (no usa Caddy ni init container).
	Ver ADR-017 para más detalles.

================================================================================
CLOUDFLARE TUNNEL — NO ES EFÍMERO
================================================================================

El túnel de Cloudflare NO es efímero. Es un recurso persistente que se configura
una sola vez y queda corriendo permanentemente:

- Se crea UNA SOLA VEZ en el dashboard de Cloudflare
- Tiene un ID fijo permanente (CLOUDFLARE_TUNNEL_ID en .env)
- Las credenciales viven en ~/.cloudflared/ como archivos JSON
- El daemon cloudflared mantiene la conexión activa permanentemente
- Si se cae, systemd lo reinicia automáticamente (Restart=always)

CÓMO FUNCIONA INTERNAMENTE:
1. cloudflared (corriendo en el VPS) abre una conexión SALIENTE a los servidores
   de Cloudflare (no necesita puertos de entrada abiertos en el VPS)
2. Cloudflare recibe las peticiones HTTPS de los usuarios en veterinaria.artisandevs.site
3. Las enruta a través del túnel hacia Nginx:81 (en el VPS)
4. Nginx las distribuye al backend o frontend

CONFIGURACIÓN DEL TÚNEL (una sola vez):

  # Crear el túnel (una vez)
  cloudflared tunnel create <nombre>

  # Configurar ~/.cloudflared/config.yml
  tunnel: 00cbc17e-2070-42b8-8a49-83728afd1273
  credentials-file: /home/kscod/.cloudflared/00cbc17e-...json

  ingress:
    - hostname: dev-api.artisandevs.site
      service: http://localhost:8000       # Dev: FastAPI directo
    - service: http_status:404            # Catch-all OBLIGATORIO

  # Routear DNS
  cloudflared tunnel route dns <tunnel-id> <hostname>

SERVICIO SYSTEMD EN PRODUCCIÓN:

  sudo tee /etc/systemd/system/cloudflared.service > /dev/null << 'EOF'
  [Unit]
  Description=Cloudflare Tunnel
  After=network.target

  [Service]
  Type=simple
  ExecStart=/usr/local/bin/cloudflared tunnel --config /root/.cloudflared/config.yml run
  Restart=always
  RestartSec=5

  [Install]
  WantedBy=multi-user.target
  EOF

  sudo systemctl daemon-reload
  sudo systemctl enable cloudflared
  sudo systemctl start cloudflared

COMANDOS ÚTILES:

  cloudflared tunnel ingress validate   # Validar configuración
  cloudflared tunnel list                # Ver túneles creados
  cloudflared tunnel info <tunnel-id>    # Info de un túnel
  journalctl -u cloudflared -f          # Logs del servicio

CODE REVIEW (AI AGENT) — code-review.yml:

  Job 1: Static Review (.github/scripts/static-review.sh)

    ├── Clean Architecture frontend (shared/ vs features/, widgets/, pages/)
    ├── No secrets hardcoded
    ├── .env no commiteado
    ├── UUIDv7 (no uuid4)
    ├── Migraciones no destructivas
    ├── Tests presentes para archivos modificados

    └── Postea comentario en el PR con veredicto (PASS/FAIL)

  Si el AI review encuentra errores críticos → el job falla → no se permite merge.
  El secret GROQ_API_KEY debe estar configurado en el repo de GitHub.

  PR Template (.github/pull_request_template.md):
    Checklist que el autor llena al abrir el PR.
